前言

平时我们使用shell命令的时候，如果命令执行时间较长，我们就要等待命令执行完毕才能执行下一条命令。时间长了，你可能会怀念GUI操作的最小化某个任务，这样我们可以在几个任务间切换，不需要经历长时间的等待。
那么，在shell里面能不能实现类似最小化的操作呢？
Linux天生是为了多任务多用户协同操作的系统，这当然是可以的。我准备在Ubuntu下实验Linux让命令在后台运行的方法。

输出重定向

我们先来解决第一个问题，首先我们要了解重定向(>)与追加重定向(>>)：
以ls命令为例，我想让它的输出写入文件list.txt里，我可以这样做:

这样在当前位置就会出现一个list.txt的文件，里面记录着ls的输出。

如果list.txt文件记录着别的文本，使用>重定向会先清空原有的文本再记录。

要想不丢失原有的记录可以使用追加重定向>>，它不会清空原有的文本，而是从原有文本末尾开始新的记录。

说到这，应该可以猜到我们可以这样解决第一个问题：

把pidgin的输出重定向到file.log里。但是在使用过程中，你会发现终端时不时会冒出pidgin的报错信息。这时为什么呢?

这就要了解一下，Linux的文件描述符:
每个Unix进程（也许守护进程除外）应该具有三个标准 POSIX 文件描述符，对应于三个标准流：

整数值 姓名 < unistd.h >符号常量 < stdio.h >文件流
0 标准输入 STDIN_FILENO 标准输入
1 标准输出 STDOUT_FILENO 标准输出
2 标准错误 STDERR_FILENO 标准错误

这三个文件描述符可以在/proc/{PID}/fd目录下找到，{PID}是任务的进程号。例如：

可以看到pidgin的进程号为36175，所以我们可以在/proc/36175/fd目录下找到pidgin的文件描述符

别的目前还不知道代表什么，但是我们知道：

  • 0代表pidgin的标准输入stdin
  • 1代表pidgin的标准输出stdout
  • 2代表pidgin的标准错误stderr

注： 更多文件描述符信息，参阅WIKI:

  • File descriptor: https://en.wikipedia.org/wiki/File_descriptor
